注释与 docstring 用中文；标识符用英文，界面文字与数据值可以是中文。九条不分语言，某门语言的具体落法写在对应的落法文件（如 python.md、react.md）或项目语言目录的项目指令里；样板文件由项目在引入处写明。

1. 每个文件第一行用一句话写它是干什么的。
2. 主流程（分几个阶段完成一件事的函数）按编号步骤写注释（`1.`、`2.`、`2.1`），一个步骤可管几行，不逐行注释。
3. 原因不能从条件本身看出的分支或提前返回，写一句「走到这里说明什么」（如 `走到这里说明上游已校验过参数`）。
4. 返回元组或特殊值时，docstring 写清每种情况的含义。
5. 不复述代码。一看就懂的行不写注释；行尾注释只写「为什么」，不写「做什么」。
6. 不留注释掉的代码和调试输出（`print`、`console.log`）；命令行与脚本的正常输出除外，见各语言落法。
7. 同一段逻辑（两行以上，或含判断的表达式）出现第二次就抽成函数。
8. 兜底式错误处理并给降级结果（`except Exception`、`.catch(() => …)`、`catch(e){}`）只放在面向用户或命令行的最外层；内部函数让错误往上抛。把底层异常转换成带上下文的异常再往上抛是允许的，吞掉才不行；失败时静默改走另一条路径（换接口、退回缓存或旧数据）来掩盖失败也不行，要降级由最外层决定并让人知道。不为上游已保证的条件再加判断或包 `try`（已校验的参数、类型已排除的空值、不会抛异常的调用），是否保证以调用链里看得到的校验或类型声明为准；看不出保证时不删检查，按第 3 条写明「走到这里说明什么」。
9. 不加、不留当前没有调用方的参数、配置项、扩展点、函数和文件；只有一个调用方、自身不带逻辑的抽象层（只转发参数的包装函数、只有一个实现的基类或接口、只为一处调用建的工厂或策略类）直接内联，出现第二个调用方再抽；为降低复杂度拆出、带有自己逻辑的辅助函数不算。

## 九条之外

- 一行只做一件事；`a and b or c` 这类要停下来想优先级的表达式拆开写。
- 不提交密钥、凭证与本机绝对路径（如 `/Users/<某人>/...`）；用环境变量、配置文件或相对路径。

## 外部操作与凭据

对外部平台与环境（云平台、DNS、数据库、部署与发布、第三方账号）的操作分三级，项目指令对某类操作另有写明的从项目指令。有写权限不等于可以写。

- **读**（不含密钥值与个人数据）：直接做，汇报写明读了什么。
- **写**（能改回去的改动，以及发布、发送消息、推送 tag 这类收不回但不销毁已有东西的操作）：动手前说清改哪个资源、改成什么、能否及怎么改回去，等用户同意；同意只管这一次，下一处改动重新问；做完在汇报写明改了什么。
- **删除或作废**（数据、资源、凭据，以及强推覆盖共享分支；说不清会不会销毁的也算）：不执行，给出操作入口与删除前要核对的项，由人操作。

密钥不经过会话：

- 不让用户把密钥值贴进对话，请用户自己写进本机环境文件（确认不会被提交）或密钥工具，代码与配置里只引用变量名。
- 不把密钥值打印到命令输出（`echo`、`cat`、`printenv` 等）；要确认时只检查是否存在、是否为空。
- 密钥值在对话或日志里出现过，按泄露处理：不再使用，提醒用户作废并重新签发。
- 新建密钥时建议一个用途一把、只给需要的权限、预发与生产分开。
