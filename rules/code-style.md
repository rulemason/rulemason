注释与 docstring 用中文；标识符用英文，界面文字与数据值可以是中文。九条不分语言，某门语言的具体落法写在对应的落法文件（如 python.md、react.md）或项目语言目录的项目指令里；样板文件由项目在引入处写明。

1. 每个文件第一行用一句话写它是干什么的。
2. 主流程（分几个阶段完成一件事的函数）按编号步骤写注释（`1.`、`2.`、`2.1`），一个步骤可管几行，不逐行注释。
3. 原因不能从条件本身看出的分支或提前返回，写一句「走到这里说明什么」（如 `走到这里说明上游已校验过参数`）。
4. 返回元组或特殊值时，docstring 写清每种情况的含义。
5. 不复述代码。一看就懂的行不写注释；行尾注释只写「为什么」，不写「做什么」。
6. 不留注释掉的代码和调试输出（`print`、`console.log`）；命令行与脚本的正常输出除外，见各语言落法。
7. 同一段逻辑（两行以上，或含判断的表达式）出现第二次就抽成函数。
8. 兜底式错误处理并给降级结果（`except Exception`、`.catch(() => …)`、`catch(e){}`）只放在面向用户或命令行的最外层；内部函数让错误往上抛。把底层异常转换成带上下文的异常再往上抛是允许的，吞掉才不行。
9. 不加当前没有调用方的参数、配置项、扩展点。

## 九条之外

- 一行只做一件事；`a and b or c` 这类要停下来想优先级的表达式拆开写。
- 不提交密钥、凭证与本机绝对路径（如 `/Users/<某人>/...`）；用环境变量、配置文件或相对路径。
