**React / TSX：**

样板文件、界面文字放在哪、目录约定由项目在引入处写明。

九条的落法：

1. 第一行一句话写用途，放在 `"use client"` 之上；不写文件路径，交互细节写在实现它的代码旁。
2. 数据加载、路由处理和超过三条语句的事件处理按编号写步骤。JSX 是布局不是流程：只在组件名或标题都没说明时，才用 `{/* 区块名 */}` 标出区块。
3. 提前返回（如 `if (!item) return null`）和条件渲染写一句「走到这里说明…」。
4. 用类型代替 docstring；只有 `null` 或其他特殊值有含义时才写 JSDoc。
5. 行尾注释写为什么（如 `pb-4 抵消缩略图容器的 py-4`），不写做什么（如 `展开调用方传入的配置`）。
6. 不留 `console.*`，不留注释掉的 JSX 或代码。
7. 同一段 JSX 出现第二次就抽成组件；同一份数据被两处读取（如页面与它的元数据）就抽成一个共用的加载函数。
8. `.catch(() => 兜底)` 只放在页面与路由处理里；工具函数和组件让错误往上抛。有路由的项目，详情页把「找不到」转成 404，其他错误交给错误页。
9. 不加当前没有调用方的 props、变体或配置。

React 额外的几条：

- 一行一条语句，事件处理也一样：不写 `() => { a(); b(); c(); }`。
- JSX 里不嵌套三元；两种以上的渲染状态抽成带提前返回的小组件。
- 读者要停下来想的 JSX 表达式（如 `[a, b].filter(Boolean).join(" · ")`）移到 `return` 之上，写成具名常量。
- 用 React Server Components 的项目默认写服务端组件，`"use client"` 只加在持有状态或副作用的叶子组件上。
- 同一串 class 用了两次就抽成常量或组件 prop；样式类名不加注释，除非是在说明不明显的对齐。

机械部分由 ESLint 以 error 级别检查：项目配置引入共享基础规则（`no-console`、`no-nested-ternary`、`no-empty`、`complexity` 上限 15；项目代码超出时按 eslint-base 的说明写递减计划），并开启 `react-hooks/exhaustive-deps`。豁免写在 ESLint 配置里并注明原因，不在代码里逐行写 `eslint-disable`。
