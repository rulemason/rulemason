## MODIFIED Requirements

### Requirement: ESLint 基础规则由项目继承

本仓库 SHALL 提供一份 ESLint 基础规则：`no-console`、`no-nested-ternary` 与 `no-empty`（空 `catch` 同样报出）为报错级别，函数复杂度上限 15；MUST NOT 收入 ESLint 已弃用的格式类规则。接入项目的 ESLint 配置 SHALL 引入这份基础规则，再加本项目的框架规则与豁免。项目当前代码超出时，SHALL 按文件在项目配置里追加条目，只放开该文件实际违反的规则、复杂度写该文件的当前值，并注明「接入前遗留，改到该文件时清掉」；新文件与未列出的文件按基础规则检查。MUST NOT 把全局上限提到当前最复杂函数的值，MUST NOT 整条关闭规则。基础规则的说明 SHALL 写明：拆分时目标是下一档以内、不刚好卡线，递减时同时看超过 15 的函数个数。

#### Scenario: 项目甲引入基础规则
- **WHEN** 在项目甲 `web/` 运行 lint
- **THEN** `no-console`、`no-nested-ternary`、`no-empty`、复杂度 15 来自本仓库，中文字面量等 React 专属规则仍在项目配置

#### Scenario: 项目乙使用复杂度棘轮
- **WHEN** 项目乙前端有两个文件复杂度超出，分别是 35 与 22，其余文件都在 15 以内
- **THEN** 项目配置里这两个文件各一条按文件的条目，复杂度分别写 35 与 22，上方注明「接入前遗留，改到该文件时清掉」；全局上限仍是 15，新建的文件按 15 检查

#### Scenario: 拆分不卡线
- **WHEN** 一个复杂度 35 的函数按说明拆分
- **THEN** 说明要求拆到下一档以内（不是刚好 15），并在递减记录里同时看超过 15 的函数个数有没有减少

#### Scenario: 项目放宽空 catch
- **WHEN** 项目乙前端在基础规则之后写 `"no-empty": ["error", { allowEmptyCatch: true }]` 并注明原因
- **THEN** 空 `catch` 不报，其他空块仍报

#### Scenario: 继承前后结果一致
- **WHEN** 两个项目从自带规则改为引入基础规则
- **THEN** 迁移前后 lint 的报告完全相同

## ADDED Requirements

### Requirement: React 落法写明重构等价性

React 落法 SHALL 有「重构等价性」一节，写明从旧写法改过来时要保持的六点：抽出的组件放在模块顶层，不在组件内部定义；状态留在原组件，hook 的调用顺序与次数不变；三元改映射表时键必须是封闭的联合类型，键来自接口任意字符串时用 `Map` 或 `if`；会给每个子元素包一层的布局容器里，不从「不渲染」改成「渲染一个返回 `null` 的组件」；惰性初始化的 `useState(() => …)` 不改成每次渲染求值；条件表达式搬进函数时短路顺序不变。这一节 MUST NOT 出现某个 UI 库或组件库的名字。

#### Scenario: 清理嵌套三元
- **WHEN** AI 按 React 落法把一个嵌套三元改成映射表，键来自接口返回的任意字符串
- **THEN** AI 按等价性一节改用 `Map` 或 `if`，汇报写明原因是键不封闭

#### Scenario: 共享正文不带库名
- **WHEN** 查看 `rules/react.md` 的「重构等价性」一节
- **THEN** 布局容器那一条用通用说法描述，没有任何 UI 库的名字
