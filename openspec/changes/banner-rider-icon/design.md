# Design

## Context

- `src/rulemason/banner.py` 现在只画 3 行半格块字标：`GLYPHS` 按字母存 `█▀▄` 字形，`render(version, footer, width, color, unicode_ok)` 在 `width >= MIN_WIDTH（60）and unicode_ok` 时画字标，否则换成一行「rulemason 版本号」；颜色只用一个 256 色（`SKY = "38;5;117"`）加 `DIM` / `BOLD`，由 `_paint` 包转义。
- `tests/test_banner.py` 直接断言输出首行是字标（`█▀▀█`），并用 `_Tty` 模拟终端的 `isatty` 与编码。
- 用户选定的图标是预览方案 B：马 26×18 像素从参考图的网格逐格描出并镜像成向右跑，兔 9×13 像素手绘，兔坐在马背上，合成 26 列 × 22 像素，半格渲染后 11 行。合成结果见文末附录。
- 动机见 proposal.md「Why」；行为要求见 specs/rulekit-cli/spec.md。

## Goals / Non-Goals

**Goals:**
- 图标与字标走同一个渲染与降级路径，`render` 的签名与调用方（`cli.py`、`init.py`）不变。
- 像素数据和配色集中在 `banner.py` 顶部，改图只改数据，不碰渲染。

**Non-Goals:**
- 不做通用的精灵合成器或图片转字符工具；只渲染这一张固定图。
- 不改 `show` / `interactive` 的判断，不加新的环境变量或配置项。

## Decisions

1. **像素数据按预合成的 26×22 字母网格放在 `banner.py`（`ICON`），字母到颜色的对应放 `ICON_COLORS`。** 字母：`t` 马身、`b` 鬃尾、`d` 蹄与眼、`w` 兔、`g` 兔的阴影、`h` 眼睛镂空、`.` 空。否决「马和兔分开存、运行时合成」：要多一套叠图代码而只有一个调用方（九条第 9 条）。否决「网格放 JSON 或文本文件随包读入」：多一次文件读取与打包配置，22 行数据放代码里更直观，和 `GLYPHS` 的做法一致。
2. **半格渲染：每两像素一个字符，上有下无 `▀`、上无下有 `▄`、上下都有 `█`。** 上下颜色不同时，上像素做前景、下像素做背景；其中一侧是默认前景色（兔）时，改用那一侧的字形配另一侧的背景色，这样默认色不需要任何前景转义。`color` 为假时把所有像素视为同色，只出 `▀▄█`，不丢像素。否决「四分块字符（`▘▝▙` 等）」：每格 2×2 像素，图标只剩 6 行高，兔子的耳朵与眼睛糊成一团。否决「无颜色时丢掉背景那一半」：马身会缺块。
3. **兔用终端默认前景色，不用 256 色白。** 浅色背景的终端上白色会隐没；默认前景色随终端主题变，暗底是白、亮底是黑。否决「256 色 255 白」：只在暗底终端可见。
4. **图标的降级条件沿用字标的（`width >= MIN_WIDTH and unicode_ok`），不另设阈值。** 图标 26 列比字标窄，60 列下限已经足够。否决「图标单独阈值」：两套条件、测试翻倍，没有收益。
5. **`NO_COLOR` 时仍画图标，单色。** 与字标在 `NO_COLOR` 下的行为一致，少一条分支；单色剪影仍是一匹马。否决「`NO_COLOR` 时跳过图标只留字标」：多一条分支，且无颜色的用户看不到标志。
6. **图标在字标上方、中间空一行，不并排。** 并排（预览方案 A）整屏要 80 列，和 60 列下限冲突；用户选了 B。

## Risks / Trade-offs

- [终端字体缺块字符或行距有缝，图标断行] → 与现有字标同一风险，编码写不出时已有 `unicode_ok` 降级；行距由终端决定，不处理。
- [浅色终端上兔的浅灰阴影（256 色 250）几乎看不见] → 阴影只是辅助，主体用默认前景色，丢了阴影仍能认出兔子。
- [`NO_COLOR` 下马和兔同色，骑手变成马背上的一团] → 接受；有颜色是主要场景，单色下剪影仍是一匹马。
- [启动画面高了 12 行，整屏约 27 行，24 行的终端要滚一下才看到常用命令] → 接受；用户在预览里看过方案 B 的高度并选定。
- [现有测试断言首行是字标] → 按新布局改断言，见 tasks 第 2 组。

## Migration Plan

- 上线顺序：改 `banner.py`（数据与渲染）→ 改 `tests/test_banner.py` → `uv run ruff check .` 与 `uv run pytest` 通过 → 在真实终端运行 `rulemason` 与 `rulemason init` 目视确认 → 一次提交。
- 回滚：revert 这一次提交，启动画面回到纯字标；没有数据、配置或副本需要迁移，接入项目不受影响。
