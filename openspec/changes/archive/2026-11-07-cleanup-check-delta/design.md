# Design

## Context

动机见 proposal.md「Why」。现状：

- 每次运行都把 `rulemason check --json` 的 `text` 原样放进汇报（`skills/rulemason/SKILL.md:22`，`openspec/specs/rules-layer-setup/spec.md:22`）。
- 存量清理仍先跑 check，`next.code` 只作入口闸门（`skills/rulemason/SKILL.md:35`、`:143`，`openspec/specs/rules-layer-setup/spec.md:322`）。
- 收尾写明汇报按第 8 节，第 8 节把 `text` 放在最前（`skills/rulemason/SKILL.md:164`、`:168`）。
- 第 7 节不超过 70 行（`tests/test_templates.py:171`）。当前这一节是 26 行（`skills/rulemason/SKILL.md:139-164`）。
- 各层没有缺失时写「齐全」，巡检项没有偏离时写「一致」（`src/rulemason/check.py:1250`、`:1254`）。

## Goals / Non-Goals

**Goals:**

- 连续进入下一个模块时，计划前面不再是整份识别表。
- 接入上真正要看的行（不是「一致」、不是「齐全」，或入口要停下）仍然出现。

**Non-Goals:**

- 不改 `check` 命令的输出。
- 不按正在清理的模块筛选巡检项。

## Decisions

1. **可以继续时只展示不是「齐全」、不是「一致」的行。** 这次对话的第一次清理写一行 `next.code`，并列出这些行；汇报第一行不是「日常巡检：一切一致」时带上该行。同一对话里再次清理，这些行没变就写「巡检与这次清理开始时相同」，有变只列变了的行。否决按当前模块过滤：巡检描述的是项目接入，副本落后、该先 `update` 的情况不在模块里，按模块过滤会把闸门藏掉。
2. **比较只发生在同一次对话，不写文件。** 新对话的第一次清理重新列出不是「一致」的项。否决把上次巡检写入 `.rulemason/` 或新文件：清理的进度本来就不另存，写入的报告会过期。
3. **`next.code` 要停下时仍贴全文并停下。** 否决停下来也只写一行：用户要凭识别表修正清单、更新副本或升级本机。
4. **收尾使用同一套展示。** 否决只改进入模块时的汇报：第 8 节仍规定全文放在最前，做完一个模块时整份巡检还会先出现。
5. **细则放在第 1 节和第 8 节，第 7 节只留一句指路。** 否决把整段细则写进第 7 节：这一节有 70 行上限，现为 26 行，清理步骤不该为汇报格式让位。

## Risks / Trade-offs

- [对话中断后代理不记得上次列出的行，又贴出全文] → 按这次对话的第一次清理处理，仍只列不是「一致」的项，不回到全文。
- [「一致」「齐全」的措辞以后改了，过滤对不上] → skill 写明以这两个词为准；改措辞时同时改 skill。
- [第 7 节超过 70 行] → 细则不进第 7 节，预计这一节增加约 2 行。
- [代理仍按第 1 节旧句贴全文] → 第 1 节改成存量清理不贴全文，测试断言「巡检与这次清理开始时相同」和「不把上次巡检写入文件」。

## Migration Plan

1. 本仓库改 skill 与测试，按检查点收尾后归档再发版。发布说明只写：连续清理模块时不再重复贴整份巡检。
2. 接入项目运行 `uv tool upgrade rulemason`，再 `rulemason update`。本机若被精确版本钉住，改用 `uv tool install rulemason@latest`。
3. 回滚：再发一版，把第 1、7、8 节和测试恢复成上一版。PyPI 上已发出的版本不能删。没有要迁移的任务文件。
