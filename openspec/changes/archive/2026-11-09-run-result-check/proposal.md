# Proposal

## Why

接入项目（首个场景：产品解读结构化输出）需要对照明确检查要求，对**已发生**的运行记录做可复核的确定性结论，把「看起来成功」与「证据上满足要求」分开。现有 `check` / `update` / `judge` 分别管副本一致性与方案评判，都不消费调用方交来的一次运行记录。

## What Changes

- 新增对「调用方提供的已发生记录 + 检查要求」的确定性检查能力：文本必须包含 / 禁止包含 / 模式；结构化可解析与必填字段；逐项结论与总体通过条件；来源 / 范围 / 限度；本地处理、不上传、不额外调模型。
- 以独立命令行入口供 CI / 脚本消费（具体子命令名与退出码映射见 design；本提案不锁定实现细节）。
- 首个接入场景约定为产品解读结构化输出：先用离线 fixture 验收；调用方日后若已有 eval 报告，可自行映射成检查输入后再交进来（本期不写报告解析、不跑付费 eval、不自动接产品 API、不改接入项目 CI）。
- 不做：
  - 不做 Skill / 工具调用出现检查（原 RR-05）；不得把未采集或不适用写成通过。
  - 不做编程 agent harness、通用会话采集、运行 agent、挂钩子或拦截 LLM。
  - 不改 `check` / `update` / `judge` 既有语义、参数或退出码含义。
  - 不改 Yaomancy（或其他接入项目）代码、护栏、工作流；不写采集器。
  - 不依赖 第三方测试或分析框架；不复制或翻译第三方实现。
  - 不承诺报告自动脱敏或默认回显完整原文；不把 fixture 冒充真实模型会话。
  - 不为日后 eval / Skill / harness 预留插件、适配层或配置开关。

## Capabilities

### New Capabilities

- `run-result-check`：对调用方提供的已发生运行记录做确定性检查，并输出可被自动化读取的逐项与汇总结论。

### Modified Capabilities

（无）

## Impact

- 本仓库：新增检查库与 CLI 子命令（apply 阶段）；测试覆盖确定性规则与退出语义；文档/帮助提及新入口。
- 既有 `rulemason check --json` schema、`judge` 的 pass/review/block 不变。
- 接入项目：可选在自身脚本中调用新入口；本期不强制改其 CI。
