# Design

## Context

动机见 proposal.md「Why」。现状：

- 不带模块名时只诊断，最后一行是 `/rulemason cleanup <模块>`（`skills/rulemason/SKILL.md:145`）。
- 进度不落文件：看「接入前遗留」是否还在，以及 `git log --grep '^refactor(cleanup):'`（`skills/rulemason/SKILL.md:153`）。收尾让用户自己提交，说明写成 `refactor(cleanup): <模块>`（`skills/rulemason/SKILL.md:162`）。
- 高、中、低来自每个模块抽 2 到 3 个文件（`openspec/specs/rules-layer-setup/spec.md:338`）。第 7 节测试要求不超过 70 行（`tests/test_templates.py:171`）。当前这一节约 25 行（`skills/rulemason/SKILL.md:139-163`）。

## Goals / Non-Goals

**Goals:**

- 同一次诊断里，队列顺序可以由提交记录、未提交文件和软指标重算出来。
- 做完一个模块的当次收尾就写出下一个命令。
- 点名下一个模块之后，仍然先列计划、等确认。

**Non-Goals:**

- 不保存高、中、低，收尾重算时也不再抽样。
- 不改六步里的通读、分组、改前证据和并行上限。

## Decisions

1. **队列按三条机械规则排序，高、中、低只标在行旁。** 先跳过已有 `refactor(cleanup): <模块>` 的模块；工作区干净的在前；再按软指标条数、行数、模块路径字典序。否决用高、中、低排序：抽样档位两次诊断会变，顺序又不落文件，下一个模块会对不上。
2. **诊断当次把潜力为低的合成一行，不把它当作现在要做的模块。** 还有工作区干净且不是低的模块时，最后一行是排序后第一条的命令。没有时，路径只从有未提交文件的模块里、按同一顺序取第一条；这种模块也没有，则写明这次没有要做的模块。否决取「队列第一条」的路径：第一条可能是干净的低潜力模块，它没有要提交的路径。否决把「低」的名单写进文件：下次收尾用不到它，写了也会过期。
3. **完成只认提交说明。** 工作区里的清理改动仍算未完成。否决把工作区改动当成完成：skill 不提交，下次会话看不到这是哪一个模块的清理。
4. **收尾把刚做完的模块视为已完成来重算，不重新抽样，也不看高、中、低。** 这一轮先排除该模块，即使提交还没落地；之后不带模块名的诊断仍只认提交。顺序与诊断相同：工作区干净的在前，再按软指标条数、行数、模块路径字典序。还有干净的未完成模块时，最后一行是排序后第一条的命令。没有时，路径取有未提交文件的模块里按软指标、行数、路径的第一条。都没有则写明这次没有要做的模块。否决收尾也排除低：档位不保存，收尾不再抽样，新会话对不上。否决只在对话里记住上次队列：新会话没有这份队列。
5. **收尾不开始改下一个模块。** 用户输入命令之后，仍走现有的通读、列计划、确认。否决收尾直接改下一个模块：模块名不是同意。

收尾重算不用档位，因此可能点到诊断里标过低的模块。这是不保存档位的结果，不另做一份例外名单。

## Risks / Trade-offs

- [用户没提交就去修下一个，两次改动混在一起] → 收尾先要求提交；没有对应提交时，下次诊断把该模块排回队列。
- [收尾点到诊断里标为低的模块] → 收尾写明这是按软指标重算的，不声称沿用上次的高、中、低。
- [第 7 节超过 70 行] → 预计增加约 15 行，现约 25 行；超出再在汇报里说明，不预先放宽上限。
- [软指标相同且行数相同] → 用模块路径字典序，顺序每次相同。

## Migration Plan

1. 本仓库改 skill 与测试，按检查点收尾后发版。
2. 接入项目运行 `uv tool upgrade rulemason`，再 `rulemason update`，按各项目惯例提交副本。本机若被精确版本钉住，改用 `uv tool install rulemason@latest`。
3. 回滚：再发一版，把第 7 节和测试恢复成上一版。PyPI 上已发出的版本不能删。没有要迁移的队列文件。
