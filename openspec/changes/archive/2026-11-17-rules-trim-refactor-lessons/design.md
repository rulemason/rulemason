- 常驻正文现为 10194 字：五份文件按 `len(Path.read_text(encoding="utf-8"))` 相加（`code-style.md` 1538、`python.md` 463、`react.md` 1535、`agent-coding-caution.md` 729、`workflow-gates.md` 5929）。
- 「修掉本次改动引入的问题……建议运行 `/rulemason` 建立基线」在 `rules/workflow-gates.md` 出现在 apply 第 2 步、第 4 步和「不走 OpenSpec 改代码时」第 4 步三处（`grep -c '修掉本次改动引入的问题' rules/workflow-gates.md` 得 3）。
- 「可选：阶段学习文档同步 Notion」是 `rules/workflow-gates.md` 的最后一节，共 161 字；`src/`、`skills/`、README 里都没有引用它（`grep -rn 'Notion\|阶段学习' src skills README.md README.en.md` 无结果）。本仓库不入库的 `CLAUDE.local.md` 只写了落点，做法靠这一节。
- 主规格 `workflow-gates` 的 Purpose（`openspec/specs/workflow-gates/spec.md:4`）提到这个可选步骤；Purpose 不随规格增量合并，要直接改。
- `tests/test_templates.py` 按原文断言规则措辞：第 262 行要求「建议运行 `/rulemason` 建立基线」恰好出现 2 次；第 411–412 行要求「4. 改了前端时」那一行含「修掉本次改动引入的问题」与「建立 ESLint 基线」；第 465 行要求 React「重构等价性」恰好 6 条。
- 下面「措辞草稿」整体代入后实算为 10253 字（在内存里替换原文后重新相加，未写文件）。

## Goals / Non-Goals

**Goals:**

- 新加的规矩都写成一句、放进已有的小节，不新开文件。
- 字数上限由测试检查，测试只数常驻的五份文件。

**Non-Goals:**

- 不调整已有句子的含义；去重与删说明句只改措辞，检查点的行为不变。
- 不改 `prose-hygiene.md`、`product-artifact-caution.md`、`copy-voice.md` 等写作类规则。

## Decisions

1. **「重构时不动被依赖的东西」放进 `code-style.md` 的「九条之外」**。否决：在 `python.md` 另开「重构等价性」一节。打桩名字、源码断言、接口文档与日志原文四件事不分语言，放在语言落法里，React 项目读不到；另开一节也更占字数。
2. **「只修本次引入」在检查点开头定义一次，各步写「按『只修本次引入』处理」**。否决：保留三处原文只删一两个从句。三处文字已开始走样（前端那步写「判断方法同第 2 步」，直接改动那步写「判断方法与遗留豁免的处理同……」），继续各写各的会再分叉。测试归因那一句也并进这段定义，不另起一节。
3. **合并上游单独成节，放在「提交与推送」之前**。否决：并进 apply 的检查步骤。合并上游与哪个 change 无关，走不走 OpenSpec 都会发生，挂在 apply 下面会被以为只在 apply 时才做。
4. **字数上限先定 10300，用户已选**。否决：坚持 10000 再压措辞，要删的多是测试点名的句子，容易删到有用的说明；也否决把「归档第 5 步改由 check 输出」挪进本 change，那会把纯文字改动变成要改代码。
5. **字数测试写在 `tests/test_templates.py`，按字符数（`len`）计**。否决：按行数计，`workflow-gates.md` 一行常有两三百字，行数反映不了加载量；也否决新建测试文件，这个文件已经集中了规则措辞的断言。
6. **Notion 一节整节删除，不留「已移除」的提示句**。否决：留一句「需要的项目写进项目指令」。那句话本身又占常驻字数，且只对少数项目有用；升级说明在 PR 正文与发版说明里写。

## 措辞草稿

实现时可以调整用词，但要保持字数测试通过，含义不变：

- `code-style.md` 第 5 条末尾：「以上几处之外默认不写注释，也不写改动经过（如「改为」「新增」），那是提交信息的事。」
- `code-style.md`「九条之外」第一条：「重构时不改、不搬别处按名字或原文依赖的东西：被测试打桩或导入的名字（要收拢就保留原名转调）、被测试按原文截取的源码片段、会进入对外接口文档的文本、日志原文。」
- `react.md` 第 2 条改为「数据加载与路由处理按编号写步骤。」；第 3 条改为「提前返回和条件渲染的原因看不出时，写一句「走到这里说明…」。」
- `react.md`「重构等价性」末尾两条：「抽取后 `react-hooks/exhaustive-deps` 要求改依赖数组，说明这处抽取不等价：放弃抽取，不改依赖数组。」「同一位置的两个 JSX 分支不抽成两个不同组件，否则切换时整块重挂载，丢失滚动、焦点与动画；外层留在父组件只抽内部，或抽成一个组件内部分支。」
- `workflow-gates.md` 开头的定义段：原 apply 第 2 步的全部内容，加「分不清某个测试失败是否本次引入时，在改前的提交上跑同一份测试；时有时无的失败，单次通过不算结论，要找出让它必然失败的条件。」
- `workflow-gates.md`「合并上游时」：「合并上游分支后、提交合并之前，运行命令表的「ruff」与「测试」，改了前端时加跑「前端 lint」。合并造成的断裂（如一侧删掉的 import 被另一侧的新代码用到）在合并提交里修好；上游带来的其他违规另开提交处理。提交钩子拦下合并提交时，经用户同意才跳过钩子，汇报写明后续怎么清理。」
- `workflow-gates.md`「没有判断层的项目」的括号保留原样：原计划删掉其中重复列举的步骤名，实现时发现旧断言依赖其中「自动代码审查」一词，按「改既有测试时」不放宽断言，改为保留。
- `SKILL.md` 第 2 节第 4 步末尾：「命令表与红线只写本项目的命令、路径与事实，不抄共享规则里的口径（如「只修本次引入」），以 `.rulemason/` 副本为准。」
- `AGENTS.md` 新增「改共享规则」一节：三条准入条件、「只出过一次的事故留在接入项目」，以及字数上限由哪条测试检查。

## Risks / Trade-offs

- [已在用 Notion 一节的接入项目，`rulemason update` 后这一步静默消失] → PR 正文与发版说明写明，附要抄进项目指令的原文。
- [去重后，原来按三处原文写的测试断言要改] → 按检查点「改既有测试时」只改成等价断言，汇报逐条列出改前改后。
- [注释收紧被读成「删掉旧注释」] → 规格写明只约束新写的代码，React 第 3 条的改动不带「删除」字样。
- [字数上限从 10300 降回 10000 被遗忘] → proposal 已写明降回的时机，第二个 change 的任务里列一条。
- [接入项目照旧版 `react.md` 写出的注释与新版不一致] → 这是预期的过渡，不要求回改，巡检不报。

## Migration Plan

1. 本仓库合并本 change，发一个补丁版本。
2. 接入项目运行 `rulemason update` 刷新副本；用到 Notion 一节的项目按发版说明把原文写进项目指令。
3. 按 AGENTS.md「额外步骤」，在一个接入项目运行 `rulemason update --dry-run` 与 `rulemason check`，确认只有规则副本变化、巡检一致。

回滚：还原本 change 的提交并再发一个补丁版本；接入项目再运行一次 `rulemason update` 即恢复旧正文。没有数据或配置迁移。
