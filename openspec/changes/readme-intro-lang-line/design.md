## Context

`init.readme_intro`（`init.py:812`）的做法：
- 按空行把 README 切成段；
- 只要段内有一行以 `#`、`![`、`<`、`[![`、`http`、`---`、`>`、`|`、```` ``` ````、`=` 开头，就跳过整段；
- 取第一段剩下的文字，截到两句。

语言切换行有两种写法：「中文 · [English](…)」以中文开头，「[English](…) · 中文」以 `[` 开头。两种都不在上面的前缀里，所以都会被取作简介。

## Goals / Non-Goals

**Goals:**
- 语言切换行、导航链接行不再被当成简介。

**Non-Goals:**
- 不做 Markdown 完整解析。

## Decisions

### D1 判断「段内只有链接与分隔符」

新增 `_links_only(text)`，判断一段是否只是链接行：
1. 把段内的 Markdown 链接 `[文字](网址)` 整个删掉；
2. 把分隔符 `·`、`|`、`/`、`、`、`,`、`，` 换成空格，按空格切成词；
3. 剩下的只有一个词（没有空格隔开的第二个词）、不超过 10 个字，且没有句末标点（`。！？.!?`），就算链接行，跳过；
4. 段内一个链接都没有时，不算链接行，照常取。

语言名（「中文」「English」「简体中文」）都是一个词，10 个字留了余量。正文去掉链接后至少还剩两个词（如「A CLI for [OpenSpec](…)」剩「A CLI for」），不会被误跳；中文正文即使没有空格，剩下的字也远多于 10 个。第 1 轮审查发现最初按「去掉空白后的字数」判断会误跳英文短简介，改为按词判断。
否决：前缀规则加 `[`。「[English](…) · 中文」能挡住，「中文 · [English](…)」挡不住，以链接开头的正文句子反而会被误跳。否决：维护一份语言名词表（中文、English、日本語……）。导航行（「[文档](…) · [示例](…)」）同样不该当简介，词表覆盖不全。

## Risks / Trade-offs

- [一句很短又带链接的简介被误跳，如「见 [文档](…)」] → 剩下的字「见」不足 10 个，会被跳过。这类句子本来就不适合当项目简介，跳过后会去取下一段，或保留占位等 `/rulemason` 补写。
- [README 用 HTML 写语言切换] → 以 `<` 开头的段落原本就跳过，不受影响。

## Migration Plan

1. 实现并通过 ruff 与测试。用本仓库的 README 跑一次 `readme_intro`，确认取到的是正文第一段。
2. 随下一版发布；已有 `AGENTS.md` 的项目不受影响。
3. 回滚：恢复 `readme_intro` 原样即可，不涉及数据。
